SmartSupply: Datenbank-Timeout in den Einstellungen konfigurierbar machen

Behoben Erledigt SmartSupply Version 5.28.0 #490

Abgeschlossen am 06. August 2026

Der Timeout der Berechnen-Query steht fest im Code (Modules/SmartSupply/Services/DatabaseService.cs:34, aktuell 60 Sekunden). Mit #423 wurde er von 30 auf 60 erhöht, das hat eine Zeit lang gereicht, greift beim Kunden inzwischen aber wieder. Ein weiteres Hochsetzen im Code bedeutet jedes Mal ein Release, deshalb soll der Wert pro Profil einstellbar werden.

Umfang

  1. Neue Spalte CommandTimeoutSeconds INT NOT NULL in arpa.SmartSupplySettings, angelegt per MigrationSmartSupplyV8 mit Default 300, registriert in MigrationService.
  2. SmartSupplySettingsDbModel liest und schreibt den Wert, Konstante DefaultCommandTimeoutSeconds = 300, Fallback auf den Default bei Werten kleiner gleich 0.
  3. IDatabaseService.GetAllSmartSupplyData(...) bekommt den Timeout als Parameter, die feste 60 entfällt. DatabaseDesignService wird mitgezogen.
  4. Eingabefeld im SmartSupply-Einstellungsfenster (sf:IntegerTextBox, 30 bis 3600 Sekunden), Wert wird nach dem Schließen des Dialogs neu eingelesen, damit er ohne Neustart greift.
  5. Fehlerbehandlung in SmartSupplyViewModel.Calculate(): try/catch/finally, Timeout wird geloggt, verständliche Meldung mit Hinweis auf die Einstellung, IsBusy im finally zurückgesetzt. Bisher bleibt die Ansicht bei einem Timeout im Ladezustand hängen und der Fehler landet in keinem Log.

Der Wert gilt nur für die Berechnen-Query. Lieferanten-, Lager- und Einstellungsabfragen bleiben beim Standard von 30 Sekunden.

Abgrenzung

Das behebt nicht die Ursache der langen Laufzeit, siehe #489 (Verkaufsmengen-Aggregation läuft über den gesamten Artikelstamm). Der einstellbare Timeout ist die Notbremse, damit der Kunde arbeiten kann, #489 bleibt offen.
