Jobby: Neue Aktion JSON zu CSV mit auswählbaren Node-Pfaden

Neu Erledigt Jobby Version 5.28.0 #480

Abgeschlossen am 04. August 2026

Ziel

Neben XML liefern Händler und Schnittstellen ihre Daten zunehmend als JSON, während alle nachgelagerten Jobby-Aktionen (JtlStockImport, WriteShoppingList, WriteSupplierOrder, JtlAmeiseImport) CSV erwarten. Eine neue Aktion soll beliebiges JSON in CSV wandeln, wobei der Nutzer auswählt, welches Objekt eine Zeile ist und welche Werte zu Spalten werden. Verschachtelte Werte und Arrays müssen funktionieren.

Schwester-Issue für XML: #479. Der Kern wird geteilt (siehe unten).

Aktion

ActionType.JsonToCsv = 28, Mapping als JSON in ActionDbModel.Settings (kein neuer Fremdschlüssel, keine Migration).

Mapping-Modell

Zwei Angaben genügen:

  1. Zeilen-Pfad: welches Objekt ist ein Datensatz, z.B. $.products[*]
  2. Spaltenliste: je Spalte ein Name, ein Pfad relativ zur Zeile und eine Obergrenze für Wiederholungen (1 bis 50)

Beispieldatei:

{ "products": [
  { "sku": "A-100",
    "stock": { "warehouse": "Z1", "qty": 42 },
    "variants": [ { "color": "rot",  "ean": "400001" },
                  { "color": "blau", "ean": "400002" } ],
    "prices":   [ { "currency": "EUR", "amount": 19.90 },
                  { "currency": "CHF", "amount": 21.50 } ] } ] }

Mapping dazu:

Spaltenname Pfad (relativ zur Zeile) Max
Artikelnummer sku 1
Bestand stock.qty 1
Lager stock.warehouse 1
Preis EUR prices[?(@.currency=='EUR')].amount 1
Variante variants[*].color 3
EAN variants[*].ean 3

Technische Basis ist JSONPath über JToken.SelectTokens aus Newtonsoft.Json, das bereits als Paketreferenz im Projekt liegt. Filter auf Arrays ([?(@.currency=='EUR')]) sind damit ohne eigenen Code möglich.

Wiederholungen horizontal ausrollen

Liefert ein Pfad mehrere Treffer, entsteht pro Treffer eine eigene Spalte, keine Sammelzelle und keine zusätzliche Zeile:

Artikelnummer;Lager;Bestand;PreisEUR;Variante1;EAN1;Variante2;EAN2;Variante3;EAN3
A-100;Z1;42;19,90;rot;400001;blau;400002;;
  • Die Spaltenzahl ergibt sich aus der konfigurierten Obergrenze, nicht aus dem Dateiinhalt. Die Kopfzeile bleibt damit über alle Läufe stabil.
  • Obergrenze wählbar von 1 bis 50, mehr nicht, sonst wird die CSV unbrauchbar breit.
  • Mehr Treffer als erlaubt werden abgeschnitten und ins Log geschrieben.
  • Spalten aus derselben Wiederholung stehen gruppiert (Variante1;EAN1;Variante2;EAN2), damit bei Staffelpreisen Menge und Preis nebeneinander liegen.

Bedienung

Niemand soll JSONPath tippen. Im Aktions-Fenster wird eine Beispieldatei geladen, die Struktur erscheint als Baum (SfTreeView ist im Projekt vorhanden), der Nutzer klickt einen Knoten an und wählt "als Zeilen-Ebene" oder "als Spalte". Den Pfad erzeugt das Tool. Das Pfad-Feld bleibt editierbar, damit Fortgeschrittene Filter nachschärfen können.

Lesen ohne Speicherproblem

Feeds können mehrere hundert MB groß sein. Der JsonTextReader läuft durch die Datei bis zum Zeilen-Pfad, lädt genau dieses Objekt per JToken.ReadFrom, wertet darauf alle Spaltenpfade aus, schreibt die Zeile und verwirft das Objekt.

Pipeline-Verhalten

  • Eingabe sind die Dateien des Vorgängers, gefiltert über action.Filter wie üblich.
  • Pro Eingabedatei entsteht eine CSV im Job-Temp-Ordner.
  • Rückgabe ist ein neues TransferObject mit den CSV-Pfaden, die JSON-Dateien werden nicht weitergereicht.

Damit sind Ketten wie diese möglich:

LoadFromWeb (api.json)     ->  JsonToCsv  ->  JtlStockImport
FtpServerDownload (*.json)  ->  JsonToCsv  ->  SaveToFolder + FtpServerUpload

Geteilter Kern mit #479

Mapping-Modelle, CSV-Writer und Ausroll-Logik sind identisch, nur die Formatgrenze ist getrennt:

Modules/Jobby/Business/Converters/
  IRowSource.cs      Rows() + Value(row, relPath)
  XmlRowSource.cs    XmlReader-Streaming + XPath   (#479)
  JsonRowSource.cs   JsonTextReader + JSONPath     (dieses Issue)
  CsvRowWriter.cs    Kopfzeile, Wiederholungsspalten, Quoting, Encoding
  RowMapping.cs      RowPath + List<ColumnMapping>
  ColumnMapping.cs   Name, Path, MaxOccurrences (1-50)

Settings-Modell, Detail-Fenster und ViewModel bleiben je Aktion getrennt, weil Pfad-Syntax, Hilfetexte und Beispiele je Format unterschiedlich sind. Wird #479 zuerst umgesetzt, entsteht dieses Issue im Wesentlichen aus JsonRowSource plus Fenster.

JSON-spezifische Punkte

  • Wurzel kann ein Array sein ([ {...}, {...} ]), Zeilen-Pfad dann $[*].
  • Skalare Arrays ("tags": ["a","b"]) müssen als Wiederholung funktionieren, nicht nur Objekt-Arrays.
  • null in JSON wird zur leeren Zelle, nicht zum Text "null".
  • Zahlen und Wahrheitswerte werden kulturunabhängig gelesen und erst beim Schreiben formatiert, sonst wird aus 19.90 versehentlich 1990.
  • NDJSON / JSON Lines (ein Objekt pro Zeile) ist zunächst nicht vorgesehen, bei Bedarf als eigener Schalter nachrüstbar.

Nicht Teil dieses Issues

  • Keine Vorlagen-Tabelle und kein Verwaltungsfenster für Mappings.
  • Kein Schalter für die Spaltenfolge, gruppiert ist fest.

Noch zu klären (kommt in die Spec)

  • CSV-Ausgabeoptionen: Trennzeichen, Kopfzeile ja/nein, Encoding, Quoting.
  • Wertetransformation je Spalte, vor allem Dezimaltrennzeichen und Datumsformate.
  • Verhalten bei fehlendem Knoten: leere Zelle oder Zeile verwerfen.
  • Verhalten bei leerer Ergebnismenge: leere CSV mit Kopfzeile oder keine Datei.
